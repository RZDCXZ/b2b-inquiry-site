# 实现询盘提交、分配与跟进闭环

Status: ready-for-agent

Blocked by: 02

Spec: [Torquelis 询盘演示系统规格](../spec.md)

## Goal

让海外采购者提交单产品或通用询盘，并让管理员和当前负责人以真实服务端权限完成通知、分配、联系、报价和关闭。

## Scope

- 建立 Inquiry、分配历史、跟进记录、通知发件箱和相关审计模型。
- 一张询盘最多关联一个 Product，也允许通用询盘，不接受附件。
- 实现必填、选填和系统自动保存字段，并保证敏感字段不进入公开日志。
- 实现服务端校验、蜜罐、最短填写时间、速率限制、一次性令牌和简单风险规则。
- 实现 POST/Redirect/GET、不可推测询盘参考号和重复提交幂等。
- 实现待分配、已分配、跟进中、已报价和已关闭状态，以及成交、未成交、无效关闭结果。
- 垃圾询盘独立隔离，不进入正常状态流转。
- 正常提交向管理员通知发件箱写入记录，分配后向当前负责人写入记录；垃圾询盘无通知。
- 实现管理员分配、重新分配、垃圾隔离和重新打开；重新打开回到已分配。
- 实现当前负责人唯一访问边界，重新分配后旧负责人立即失去完整访问。
- 实现联系、报价、内部备注和更正记录；记录追加后不可覆盖或删除。
- 首次联系推进跟进中，报价推进已报价；关闭必须有关闭结果。
- 报价使用十进制定点金额、USD／EUR／CNY 和有效期，不生成报价单。
- 实现乐观并发版本检查。
- 实现询盘列表、详情、状态筛选、到期跟进、关闭结果和通知发件箱中文后台。
- 准备 20 张覆盖不同来源、状态、负责人、垃圾和关闭结果的演示询盘。

## Acceptance Criteria

- 产品详情询盘自动关联当前产品，通用询盘没有产品关联。
- 正常提交生成一张待分配询盘、一条管理员通知和一个不泄露敏感信息的成功页。
- 同一一次性令牌重复提交返回原结果，不创建第二张询盘或第二条通知。
- 超速或风险提交按规则进入垃圾询盘区，不触发通知。
- 管理员分配后产生当前负责人通知；业务人员能看到完整信息并追加首次联系。
- 首次联系、报价和关闭按事件自动推进到正确状态。
- 报价记录包含定点金额、币种和有效期，但没有独立报价单。
- 重新分配后旧负责人立即得到权限拒绝，新负责人获得访问；历史分配和操作保留。
- 业务人员不能访问未分配询盘、内容、导入、设置或审计页面。
- 内容编辑只能看到脱敏数量，不能打开询盘和通知内容。
- 已关闭询盘只有管理员可重新打开，并回到已分配。
- 跟进记录不可修改或删除，更正以新记录表达。
- 并发旧版本分配或状态操作被拒绝，并显示最新修改人和时间。
- 审计记录动作摘要但不复制完整联系方式、留言、密码或会话。

## Testing

- 单元测试覆盖状态机、关闭结果、风险规则、权限矩阵、跟进类型和金额校验所有分支。
- 真实 PostgreSQL 集成测试覆盖幂等提交、分配／重新分配权限、通知、垃圾隔离、并发冲突和审计脱敏。
- Playwright 串联英文产品页提交、中文管理员分配、业务人员联系／报价／关闭和旧负责人权限拒绝。
- 覆盖正常、重复、超速、可疑提交和成功页刷新。

## Out of Scope

- 询盘附件、多产品 RFQ、报价单、客户账户和邮件同步。
- 真实邮件、短信、WhatsApp 或 CRM 集成。
- 销售漏斗、样品、合同、回款和营销自动化。
