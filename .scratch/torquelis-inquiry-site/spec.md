# Torquelis 商用车滤清器多语言询盘演示系统

Status: ready-for-agent

## Problem Statement

小宇需要一个能促成中国中小制造企业老板或外贸负责人预约需求沟通的自由职业作品集项目。普通企业官网只能证明页面制作能力，无法充分证明他能够理解制造业产品目录、海外采购者的产品查找方式、结构化询盘、业务分配跟进、多语言发布、批量数据迁移和可复现交付。

项目没有真实客户、真实产品参数或公开生产环境，因此又必须清楚区分可验证的软件能力与无法证明的认证、流量、排名、询盘量和成交结果。成品需要在本地稳定运行，完整代码可以公开审阅，但不能依赖小宇个人电脑上的隐藏配置、个人账号或外部服务。

## Solution

建设一套以虚构商用车滤清器制造商 Torquelis Filters／拓擎利滤清为主体的本地演示系统。英文优先、简体中文次要的采购前台帮助海外采购者通过产品编号、参考号、商用车型或分类规格找到标准替换件，查看双语规格资料，并提交最多关联一个产品的结构化询盘。简体中文运营后台让管理员分配和处理询盘、业务人员追加联系与报价记录、内容编辑维护双语内容和通过 Excel 批量更新产品。

系统使用真实的本地 PostgreSQL 持久化、数据库会话、服务端权限、事务导入、内容发布版本和审计历史；邮件等外部服务由明确标注的通知发件箱模拟。项目不公开部署，默认禁止搜索引擎索引，最终通过公开代码仓库、干净克隆启动、自动化检查、截图、3–5 分钟主视频和案例文章证明能力。

## Implementation Decisions

### 产品与展示边界

- 演示企业使用 Torquelis Filters／拓擎利滤清名称，主营商用车空气、机油、燃油和空调滤清器标准替换件，并提供贴牌与包装定制。
- 演示企业、产品、品牌、参考号、车辆、性能参数、文章、询盘、报价和统计均为虚构数据。不得展示客户 Logo、评价、认证徽章、检测报告或无法验证的工厂资历。
- 前台页脚、隐私与演示数据说明页、规格 PDF、截图和录屏持续标明虚构演示性质。品牌名只完成公开网络初筛，不代表正式商标检索。
- 系统只在本地运行，不公开部署。完整仓库公开但不附开源许可证，默认版权规则适用。
- macOS 是人工演示平台，Linux 是 CI 验证平台；Windows 不属于完成承诺。

### 架构与模块

- 使用 Next.js App Router、React、TypeScript 和 Tailwind CSS 构建一个模块化单体，同时承载英文／中文采购前台、简体中文后台和服务端业务。
- 业务模块按产品目录、内容发布、询盘运营、身份权限、通知和站点配置划分。页面和服务端入口只编排用例，不直接承载跨模块领域逻辑。
- 使用 PostgreSQL 作为唯一业务数据库，并由 Docker Compose 在本地运行。
- Prisma 负责模型、迁移和常规类型安全数据访问；复杂目录筛选允许使用封装后的参数化 SQL。
- Zod 在服务端边界重新校验表单、URL 参数、Excel 数据和后台操作，不信任浏览器端校验。
- Better Auth 只启用预置账号所需的邮箱密码和数据库会话。关闭注册、找回密码、邮件验证、社交登录和账号管理；角色授权由业务服务端显式执行。
- 数据库时间统一保存为 UTC；英文和中文前台使用各自语言格式，中文后台固定使用 Asia/Shanghai。
- 报价金额使用十进制定点数和 ISO 4217 币种代码，只生成 USD、EUR 和 CNY 演示数据，不做汇率换算。

### 本地启动、凭据与重置

- 本地环境要求锁定版本的 Node.js、pnpm 和 Docker。
- setup 合同包含创建未跟踪环境文件、随机会话密钥、启动数据库、执行版本化迁移、生成演示素材、载入数据和生成随机预置账号密码。
- 随机账号密码写入被忽略的本地凭据文件并在 setup 终端输出。凭据查看命令必须验证当前目标是本地演示环境。
- 演示重置只能通过 CLI 执行。命令必须验证数据库主机、数据库标识和演示环境标记，拒绝非本地或身份不明目标。
- 重置恢复固定数据、发布版本、通知、审计和生成素材，并清理临时上传；后台不提供重置按钮。

### 身份与权限

- 角色为匿名海外采购者、业务人员、内容编辑和管理员。
- 业务人员只可读取和处理当前分配询盘，不能进入内容、导入、设置或审计页面。
- 内容编辑可维护与发布产品、分类、核心页面、文章和素材，并执行导入、导出和版本恢复；只能查看脱敏询盘数量。
- 管理员拥有全部后台权限，重点负责询盘分配、重新分配、垃圾隔离、重新打开、站点配置和全局审查。
- 当前负责人是除管理员外唯一能查看询盘完整联系方式和内部记录的业务人员。重新分配后旧负责人立即失去访问权，但历史操作保留。
- 后台导航与服务端权限使用同一矩阵；界面隐藏不是授权边界。

### 产品目录

- 每个可供应零件是一个 Product，具有语言无关 ID 和全站唯一产品编号；不建立产品系列变体。
- 产品状态为草稿、已发布和已停产。已停产产品保留 URL、规格、历史询盘和可选替代产品。
- 产品具有中英文公开内容、参考号、规格属性值、适配关系和资料关联。
- 产品参考号包含所属虚构品牌。标准化后允许同一参考号对应多个产品。
- 产品编号和参考号查找忽略大小写、空格和连字符。精确产品编号优先且直达详情；参考号始终显示结果页；不做编辑距离模糊匹配。
- 适配关系包含商用车品牌、车型、适用年份范围和发动机型号，不实现 VIN 查询。
- 分类固定为空气、机油、燃油和空调四个单层分类，不实现分类树。
- 分类配置强类型规格属性定义，包括名称、数据类型、基准单位、选项、必填性和可筛选性，并统一驱动后台表单、Excel 校验、规格表和前台筛选。
- 空气滤清器初始字段为外径、内径、高度、滤材类型和额定空气流量。
- 机油滤清器初始字段为结构形式、外径、内径、高度、螺纹规格、旁通阀开启压力和止回阀。
- 燃油滤清器初始字段为结构形式、外径、高度、接口规格、过滤精度、额定流量和油水分离。
- 空调滤清器初始字段为长度、宽度、高度、滤材类型和额定空气流量。
- 可换算数值以公制保存，英制为明确标识的派生显示；螺纹和接口等使用文本或枚举。
- 性能字段只保存明确标为不可用于选型或采购的演示性能数据。

### 查找、路由与产品页面

- 英文路由前缀为 /en，简体中文为 /zh-cn，根地址固定重定向到英文；不根据浏览器语言自动跳转。
- 产品 URL 由语言、产品编号和本地化名称组成，身份以产品编号为准。本地化名称变化后旧 URL 永久重定向到当前 URL。
- 语言切换优先定位同一业务实体。文章缺少目标语言时显示暂无版本，不拼接内容、不制造目标语言路由。
- 产品中心提供编号查找、车型查找和分类规格筛选三条入口。
- 车型查找按品牌、车型、年份、发动机和分类级联。
- 车型与规格结果按产品编号稳定排序，每页 12 项。筛选、单位和页码进入 URL；不增加自定义排序或智能相关性。
- 搜索无结果时保留条件，并提供清除筛选、编号查找和通用询盘入口。
- 产品详情展示产品编号、中英文内容、分类规格、参考号、适配摘要、相关产品、已停产／替代信息和规格 PDF。
- 每个已发布产品生成中英文轻量 PDF，包含产品编号、尺寸、适配摘要、参考号和演示水印；后台可用新的 PDF 素材替换。

### 询盘运营

- 一张 Inquiry 最多关联一个 Product，也允许成为不关联产品的通用询盘；不建立多条目 RFQ。
- 必填字段为姓名、工作邮箱、公司、国家或地区、预计采购数量、留言和隐私同意。
- 选填字段为电话或 WhatsApp、目标销售市场、贴牌需求和定制包装需求；不强制企业域名邮箱，不接受附件。
- 系统自动保存来源页面、产品、界面语言和提交时间，敏感字段不得进入公开日志或分析事件。
- 防垃圾机制包含蜜罐、最短填写时间、服务端速率限制、一次性提交令牌和简单风险规则。可疑提交进入垃圾询盘区且不触发通知。
- 提交采用 POST/Redirect/GET 和一次性令牌幂等语义。重复请求返回原成功结果，不创建第二张询盘。
- 成功页显示不可推测的询盘参考号、可选产品编号和通用下一步，不回显联系方式或留言，不提供公开查询入口。
- 正常状态机为待分配、已分配、跟进中、已报价和已关闭。关闭结果为成交、未成交或无效；垃圾询盘独立隔离。
- 正常提交产生管理员通知；分配产生当前负责人通知；垃圾询盘无通知。通知发件箱只说明已捕获，不声称真实投递。
- 管理员可分配、重新分配、垃圾隔离和重新打开；重新打开回到已分配。
- 当前负责人追加联系、报价和内部备注三类跟进记录。记录包含发生时间、操作人、摘要和下一步日期；报价另有定点金额、币种和有效期。
- 跟进记录不可覆盖或删除，错误通过追加更正记录处理。首次联系和报价记录自动推进状态。

### 内容、发布与素材

- 核心页面使用预设强类型版块，不建设任意页面搭建器。
- 产品描述和文章使用受限富文本，只允许标题、段落、列表、链接、图片和强调；禁止脚本、内嵌样式、iframe 和任意 HTML。
- 产品、分类和核心页面必须中英文满足校验后一起发布；文章按语言独立发布。
- 产品公开表示、分类、核心页面和文章每次发布形成不可变发布版本。
- 恢复发布版本只创建新草稿，经预览和再次发布后生效，不直接覆盖当前公开内容。
- 内容可归档并保留历史。已发布产品、内容、询盘、跟进、导入批次和审计日志不硬删除；只有从未发布且无引用和历史的草稿可永久删除。
- 草稿、询盘分配和状态操作使用版本号做乐观并发控制。旧版本操作被拒绝，并返回最新修改人和时间。
- 图片只接受 JPEG、PNG、WebP，资料只接受 PDF；同时校验声明 MIME、文件签名和体积，并生成安全文件名。
- 图片要求中英文替代文本。已发布内容引用的素材不可删除；替换资料创建新素材记录。

### Excel 导入

- 工作簿包含产品、翻译、规格值、参考号和适配关系五个工作表，以产品编号为跨表身份键。
- 已存在产品编号更新草稿，不存在则创建草稿；未出现产品保持不变，不隐式删除或停产。
- 预览必须收集全部错误。错误包含工作表、行号、字段、稳定错误代码和修正建议，并支持下载报告。
- 任一错误阻止整个导入批次；确认后的导入在一个数据库事务中执行，只更新草稿且不自动公开。
- 导入批次在所有受影响草稿尚未发布且未继续修改时可以整批撤销。
- 任一受影响草稿在导入后发布或再次修改会形成导入冲突，拒绝整批撤销并列出冲突对象。
- 已发布内容的恢复只通过发布版本完成，导入撤销不得改动公开版本。

### 站点内容、SEO 与演示数据

- 一级导航为首页、产品中心、贴牌服务、制造与品控、技术资源、关于我们和联系／通用询盘。
- 首页主要动作是查找滤清器，次要动作是提交询盘。
- 准备 4 个分类、50 个产品、6 个虚构商用车品牌、12 个车型、12 个发动机、约 150 条适配关系、每产品 2–4 个虚构参考号和 20 张不同状态询盘。
- 准备 8 个原创文章主题，其中 6 个中英文发布、2 个仅英文发布；范围削减时可降到 4 个主题，但必须保留缺失语言场景。
- 后台总览只显示可从数据库推导的询盘状态、来源、待分配、到期跟进、关闭结果和最近导入批次。
- 默认输出 noindex 并在 Robots 中禁止抓取，Canonical 示例基址使用保留的 torquelis.example。
- 只有显式开启公开索引模式时才生成可索引行为、Hreflang、站点地图和结构化数据；测试覆盖两种模式。
- 不接入第三方分析和营销脚本。前台无非必要 Cookie，不显示虚假同意横幅；后台使用必要会话 Cookie。

### 审计、配置与错误反馈

- 审计日志覆盖登录结果、发布与恢复、导入与撤销、产品停产、询盘分配、重新打开、垃圾隔离、跟进追加和站点配置修改。
- 审计项保存操作人、时间、动作、对象和变更摘要，不复制密码、会话、完整联系方式或留言；日志只读且无删除入口。
- 站点配置只包含企业中英文名称、联系信息、地址、社交链接、默认 SEO 和模拟通知收件角色。
- 索引开关、数据库地址、会话密钥和其他安全配置只来自环境变量。
- 后台无数据时提供解释性空状态。保存冲突、权限拒绝、资源不存在和系统错误使用不同反馈，不显示堆栈或敏感信息。

### 视觉与动效

- 视觉使用工业编辑风：深海军蓝、石墨灰、暖白和少量安全橙，大留白、清楚规格表和原创技术线稿。
- 后台沿用同一字色系统但提高数据密度，不使用营销式仪表盘动效。
- 动效仅用于导航、筛选结果、表单反馈和页面进入，保持短促并尊重减少动态效果设置。
- 不使用滚动劫持、3D 产品、背景视频、霓虹或重玻璃拟态。

### 公开仓库与作品证据

- 仓库文档覆盖定位、虚构声明、本地启动、凭据获取、常用检查、架构边界、数据模型、术语表、权限矩阵、Excel 字段字典、错误代码、固定演示、重置、素材许可和已知边界。
- 主视频为 3–5 分钟中文旁白和简短中文字幕，串联英文采购端、中文运营端、Excel 内容运营、自动化检查、架构图和重置。
- 案例文章补充技术细节，明确本地模拟通知、默认禁止索引、无真实认证或商业结果。
- 若范围需要削减，依次削减装饰动效、后台图表、文章数量和数据数量；不得削减产品查找、询盘闭环、权限、Excel 错误预览、内容版本恢复和干净克隆启动。

## Testing Decisions

### 测试原则与接缝

- 好测试验证参与者可观察的行为、持久化结果、权限结果、重定向、下载内容和错误合同，不断言私有函数、组件内部状态或 ORM 调用次数。
- 最高测试接缝是完整的公开浏览器流程和 CLI 合同：干净 setup、产品查找、询盘闭环、Excel 内容运营和演示重置。只要能在这个接缝稳定验证，就不为同一行为重复增加低层测试。
- 第二接缝是模块公开用例服务和真实 PostgreSQL 事务边界，用于在不启动完整浏览器时验证权限、状态变化、导入原子性和并发冲突。
- 最低接缝只用于无 I/O 的纯领域规则，如编号标准化、单位换算、状态迁移判定和错误代码映射。
- 当前仓库没有应用源码或既有测试，因此不存在可复用的代码测试先例。应把新模块公开用例作为少量稳定接缝，避免页面、API 和后台操作各自复制业务测试。

### 单元测试

- 使用 Vitest 覆盖产品编号与参考号标准化、匹配优先级和歧义参考号行为。
- 覆盖四类规格属性数据类型、必填、枚举、单位换算和不可换算字段。
- 覆盖产品、文章和核心页面的语言发布资格。
- 覆盖询盘状态机所有允许与拒绝迁移、关闭结果和垃圾隔离。
- 覆盖跟进记录类型、自动状态推进、更正记录和金额校验。
- 覆盖权限矩阵所有角色、资源和操作分支。
- 覆盖导入错误代码、跨表引用规则、编号冲突和撤销资格判定。
- 覆盖 SEO 默认／公开模式决策和多语言路由生成规则。
- 关键规则必须覆盖所有分支；不设置容易被凑数的全局覆盖率门槛。

### PostgreSQL 集成测试

- 对全新数据库执行完整迁移并载入最小 fixture。
- 验证产品、参考号、适配关系、规格属性、发布版本和素材引用约束。
- 验证精确编号、歧义参考号、车型级联和规格筛选的真实查询结果与稳定排序。
- 验证 Excel 五工作表全量错误收集、任一错误整批回滚、成功批次原子提交。
- 验证导入撤销、发布后冲突、后续编辑冲突和冲突对象报告。
- 验证发布恢复只创建新草稿，重新发布才改变公开内容。
- 验证询盘幂等提交、通知发件箱、垃圾询盘无通知、分配和重新分配访问权。
- 验证乐观并发冲突不会覆盖较新草稿、分配或状态。
- 验证审计日志存在且不含禁止复制的敏感字段。
- 测试使用隔离数据库和事务／清理策略，不能连接个人演示数据库。

### 浏览器端到端测试

- Playwright 覆盖根地址到英文、语言切换和缺失文章语言提示。
- 覆盖精确产品编号直达、参考号结果和歧义结果。
- 覆盖车型＋年份＋发动机＋分类＋规格找到固定唯一产品。
- 覆盖 URL 持久筛选、公英制切换、分页、无结果恢复和产品旧 URL 重定向。
- 覆盖产品 PDF 下载、演示水印和双语资料对应。
- 覆盖正常询盘、重复提交、超速／可疑提交、成功回执和无敏感回显。
- 覆盖管理员通知、分配、业务人员首次联系、报价、关闭和重新分配后的权限拒绝。
- 覆盖内容编辑的 Excel 错误预览、下载错误报告、导入、撤销、再次导入、预览和发布。
- 覆盖发布版本恢复为草稿、重新发布和缺失语言不生成路由。
- 覆盖素材类型拒绝、引用中的素材不可删除和替换新记录。
- 固定路径在 Chromium、Firefox 和 WebKit 的桌面及关键移动视口运行。
- 不设 Lighthouse 分数或 WCAG 符合等级；保留响应式、键盘操作、语义和错误提示的人工冒烟检查。

### CLI、CI 与复现测试

- 在干净克隆中验证 setup 后可以启动，不使用作者已有环境文件、数据库或凭据。
- 验证凭据查看和演示重置对非本地或身份不明数据库拒绝执行。
- 验证重置后 fixture 数量、固定查找场景、账号角色和生成素材恢复一致。
- GitHub Actions 在 Linux 执行格式检查、Lint、类型检查、全新迁移、单元测试、集成测试、生产构建和三浏览器路径。
- CI 产出覆盖率和浏览器报告，但完成判断以关键业务矩阵和固定路径为准。

## Out of Scope

- 公开部署、生产域名、真实云数据库、对象存储、邮件投递、监控、备份和灾备。
- 客户自助注册、多租户、订阅计费或 SaaS 运营。
- 真实客户数据、真实供应商品牌、真实产品参数、实验报告、认证、客户评价或经营成果。
- 零售购物车、支付、税务、物流、退换货和订单履约。
- 多产品 RFQ、询价车、批量采购附件和询盘文件上传。
- 完整 CRM、客户管理、独立报价单、样品、合同、回款、营销自动化和企业微信／邮件营销。
- VIN 查询、外部车辆数据库、全文搜索服务、模糊零件号纠错、智能推荐和用户自定义排序。
- 产品变体、任意深度分类树、通用页面搭建器、任意 HTML 或第三方无头 CMS。
- 后台账号新增、角色修改、密码重置、公开注册、找回密码和第三方登录。
- 多语言后台、超过中英文的翻译工作流和机器翻译自动发布。
- 第三方分析、营销 Cookie、虚假 Cookie 同意横幅、A/B 测试和高级经营分析。
- 硬删除已发布业务历史、逐字段撤销或完整事件溯源。
- 微服务、独立前端与 API 服务、云基础设施和跨服务扩缩容。
- 正式 WCAG 认证、Lighthouse 分数承诺或生产环境性能承诺。
- Windows 人工支持承诺。
- 自动抓取或复制其他企业的产品、文章、图片和资料。
- Google 排名、访问量、询盘量、成交额或任何运营结果承诺。
- 将公开仓库作为可自由复用的开源模板发布。

## Further Notes

- 规格遵循项目术语表与四份已接受 ADR：发布内容版本化与草稿导入撤销、分类可配置强类型规格属性、模块化单体与本地 PostgreSQL、Prisma／Better Auth／分层测试边界。
- 品牌候选经过公开网络明显撞名初筛，但正式商业使用前仍需在目标市场进行商标检索。
- 演示数据目标为 50 个产品而非越多越好。数据价值来自多对多关系、歧义参考号、停产替代、缺失语言、垃圾询盘、导入错误与冲突等可验证场景。
- 关键固定场景必须能通过商用车品牌、车型、年份、发动机、分类和规格推导到唯一产品，并继续形成一张结构化询盘。
- 主视频顺序为英文前台查找与资料、询盘提交、中文后台通知与分配、业务跟进与报价、Excel 错误／撤销／发布、自动化检查／架构／重置。
- 完成标准是本地系统、固定演示路径、公开仓库文档和作品材料全部可复现，不以发布后的咨询量作为项目是否完成的条件。
