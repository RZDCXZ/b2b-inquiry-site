# 模块边界

应用采用单个 Next.js 进程和单个 PostgreSQL 的模块化单体。`app/**`、CLI 和未来的 route handler 是入口层，只负责解析请求、选择语言、执行权限检查和编排用例；领域规则与持久化行为放在对应业务模块。

## 目录合同

```text
src/
├── application/                # 跨模块用例与本地演示编排
├── components/                 # 无业务所有权的共享界面组件
├── infrastructure/             # Prisma、文件系统等技术适配器
└── modules/
    ├── catalog/                # 产品、分类、规格、参考号与适配关系
    ├── content-publishing/      # 双语内容、草稿与不可变发布版本
    ├── inquiry-operations/      # 询盘、分配、跟进与关闭
    ├── identity-access/         # 账号、会话、角色与权限矩阵
    ├── notifications/           # 本地通知发件箱与通知端口
    └── site-config/             # 企业资料、语言、SEO 与演示环境身份
```

每个模块可包含：

- `public/`：其他模块和入口层可以依赖的稳定类型、查询或用例。
- `server/`：仅服务端使用的持久化和实现细节，不允许由 React 客户端组件导入。
- 模块根部 `README.md`：明确所有权与明确不拥有的能力。

## 依赖规则

1. 页面不直接访问 Prisma，也不实现跨模块领域规则。
2. 客户端组件只能导入模块的 `public/`，不能导入 `server/` 或生成的 Prisma Client。
3. 一个模块需要另一个模块的能力时，只依赖对方的 `public/`；跨模块工作流由入口层或明确的应用用例编排。
4. Prisma 生成代码只允许由服务端适配器和模块服务端实现使用。
5. 模块不能通过读取对方数据库表绕过公开用例。共享数据库是部署选择，不是共享所有权。

当前 ticket 只实现了语言内容、演示账号与站点环境身份的最小纵向切片；其余模块先锁定所有权，后续 ticket 在这些目录内增加公开用例。
